# Sheltered Mod Manager — Nexus Application Registration Review

## Application identity

- Name: Sheltered Mod Manager
- Review version: 2.0.0
- Nexus game domain: `sheltered`
- Nexus manager page: `https://www.nexusmods.com/sheltered/mods/1`
- Source: `https://github.com/coolnether123/shelteredmodmanager`
- License: MIT

Sheltered Mod Manager is a Windows desktop manager and modding framework for Sheltered. Its Nexus integration browses Sheltered mods, checks installed versions, resolves user-authorized download mirrors, safely installs compatible ZIP packages, and opens manual Nexus pages when a file cannot be installed directly. Legacy file-list `manager` metadata is not treated as authoritative because current Sheltered files report it inconsistently; the download-link endpoint or website-issued authorization makes the final access decision.

## OAuth application registration

- Application type: public Windows desktop application
- OAuth flow: authorization code with PKCE (`S256`)
- Callback URI: `http://127.0.0.1:52147/callback`
- Client secret: none; SMM is a public client and never embeds or transmits one

The callback receiver is implemented in the review source. It binds a temporary TCP listener exclusively to `127.0.0.1`, starts only while the user is signing in, accepts only the expected `/callback` GET request, validates a cryptographically random `state`, and stops after success or a five-minute timeout. PKCE verifiers and state values are created with `RandomNumberGenerator`; the authorization code is exchanged only with `https://users.nexusmods.com/oauth/token`.

The client ID remains intentionally empty until Nexus approves and registers the application. Once issued, it is inserted in `NexusOAuthConfiguration.ClientId`; no other OAuth code or callback change is required.

## Reviewer setup

1. Place the included `SMM` folder inside a Sheltered installation directory, or launch `SMM\Manager.exe` directly to review metadata browsing without a game install.
2. Open Settings > Nexus and enable Nexus features.
3. Before registration, the UI reports that OAuth registration is pending and displays the exact loopback callback. No alternate authenticated credential can be entered or selected.
4. After Nexus supplies the client ID, choose **Sign in with Nexus**. SMM opens the system browser and waits locally for the OAuth callback.
5. Open the Nexus tab and verify Discover, the Manager update check, and an installed-mod update check.
6. Select an installable Sheltered mod and choose Install.

## Download behavior

- Premium: the Manager requests mirrors through the official v1 download-link endpoint.
- Non-premium/supporter: Nexus requires a short-lived `key` and `expires` authorization generated by the website's Mod Manager Download action. SMM temporarily registers for the next `nxm://` link, restores the user's previous handler immediately after capture or automatically after 15 minutes, validates the link, and then requests the mirror through the same official endpoint.
- Resolved mirror URLs and nxm authorization values are never cached. Cross-process nxm relay files are DPAPI-encrypted and deleted after consumption.
- OAuth access and refresh tokens are stored only in DPAPI CurrentUser-protected settings values. They are refreshed before expiry and removed by **Sign out**.
- SMM currently installs ZIP packages only and validates the package structure and target before replacing files.
- Rollback backups stay on the configured mods volume, allowing safe updates when the Manager executable and the managed Sheltered installation are on different drives.

## API selection

- v2 GraphQL is used for low-request metadata browsing and batched update checks.
- v1 remains in use for credential validation, file listing fallback, and download-link resolution because these capabilities are not available in the v3 OpenAPI.
- v3 stable upload-session endpoints and current experimental mod-file endpoints exist in dormant author tooling. API publishing is forcibly disabled in public 2.0 builds pending separate Nexus approval.
- Authenticated access uses OAuth bearer tokens exclusively. Failed or revoked sessions are cleared and require OAuth reconnection; there is no personal-key fallback.

Every Nexus API request includes:

- `Application-Name: Sheltered Mod Manager`
- `Application-Version: 2.0.0`
- `User-Agent: ShelteredModManager/2.0.0`

## Rate-limit handling

SMM reads the Nexus `X-RL-Hourly-Remaining` and `X-RL-Daily-Remaining` response headers for v1, v2 GraphQL, and v3 API requests. Quotas are isolated by credential, concurrent requests reserve known remaining capacity before sending, and out-of-order responses cannot restore stale capacity. When a quota is exhausted, SMM stops issuing API requests for that credential until the applicable UTC hour or day rolls over. Server `Date` values are used to associate responses with the correct quota window when available.

HTTP 429 responses produce an actionable user-facing error. Reservations are restored only for failures that prove the request did not reach Nexus, such as DNS, connection, or TLS negotiation failures without an HTTP response. Presigned upload requests remain outside this handling and never receive Nexus authentication or application-identification headers.

## Suggested review cases

- Valid, expired, refreshable, invalid, and revoked OAuth sessions, including confirmation that failures require reconnection.
- OAuth approval, denial, state mismatch, timeout, refresh, revocation, sign-out, and occupied callback port.
- Premium direct download.
- Regular-member website-authorized Mod Manager Download.
- A file that disallows manager download.
- Deleted/hidden file, offline request, timeout, and HTTP 429 response.
- ZIP package with an invalid SMM layout and an attempted duplicate mod ID.
